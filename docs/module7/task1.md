7.7. Глаза дракона

В этом задании мы закончим основные работы по имплементации REST API: допишем недостающие обработчики маршрутов, и добавим контроллер для ресурса «Комментарии». После этого потренируемся в создании собственных middleware. На их плечи можно переложить часть работ, которые по умолчанию хочется выполнить в контроллере. Например, задачи, связанные с валидацией.

+1. Завершите имплементацию REST API (пересмотрите соответствующий раздел технического задания). +Реализуйте контроллер для ресурса «Комментарии». +Клиенты могут только добавлять комментарии. +Удаление и редактирование комментариев не предусмотрено. +Обратите внимание: пока мы не разделяем обработку запросов от авторизованных и неавторизованных клиентов. На текущем шаге анонимные клиенты могут выполнять любые запросы.
+При имплементации обработчиков маршрутов соблюдайте консистентность: используйте одинаковые имена для обработчиков одних и тех же действий в разных контроллерах. Например: create (для создания новых сущностей), update (редактирование или обновление), delete (удаление), show (для чтения определённой сущности) и index (для получения списка сущностей).

+2. Спроектируйте абстракцию «Middleware». Вам потребуется отдельный интерфейс. Модифицируйте интерфейс описания маршрутов. Добавьте поддержку применения middleware для определённого маршрута. Помните, для одного маршрута может применяться несколько middleware, а может не применяться ни одной. Предусмотрите этот сценарий. Модифицируйте абстрактный контроллер, добавьте поддержку middleware.

+3. Реализуйте первую middleware для проверки корректности ObjectID. Если клиент передаёт некорректный идентификатор сущности, сервер должен корректно обрабатывать эту ситуацию. Например, возвращать в качестве кода состояния 400 (Bad Request). После разработки подключите созданную middleware ко всем обработчикам маршрутов, где клиент передаёт идентификатор сущности.

4. Установите пакет class-validator и воспользуйтесь декораторами-валидаторов в DTO. Все ограничения и правила валидации определены в техническом задании к проекту. Вместо пакета class-validator вы можете воспользоваться альтернативным решением в виде joi. Информация о применении joi есть в учебнике.

5. Создайте новую middleware и реализуйте в ней валидацию данных, полученных от клиента. Данные не должны использоваться без предварительной валидации. Подключите созданную middleware к нужным обработчикам. В качестве дополнительного задания (сейчас это делать необязательно) можете продумать в каком виде лучше возвращать ошибки при валидации.
